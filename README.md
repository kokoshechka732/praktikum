# Практикум: три кейса по анализу данных

Учебная производственная практика. Три задания: поиск аномалий в журнале заявок, восстановление
бизнес-процесса по журналу событий и генерация продуктовых гипотез по дампу БД подписочного сервиса.
По каждому кейсу — отчёт, результаты в требуемом формате и код, которым эти результаты считаются.

| Кейс | Задача | Что сдаётся |
|---|---|---|
| [Кейс 1](Кейс1/) | найти нетипичное поведение заявок на закупку | `anomalies.csv` — 66 строк по 56 заявкам, отчёт, `analysis.py` |
| [Кейс 2](Кейс2/) | восстановить процесс по журналу без схемы | `schema.svg`, `variants.csv`, `student_transitions.csv`, отчёт, код |
| [Кейс 3](Кейс3/) | продуктовые гипотезы по данным VPN-сервиса | отчёт с 6 гипотезами, `out/*.json`, код на DuckDB |

В каждой папке свой `README.md`: что за данные, что получилось, как пересчитать.

## Как запустить

Нужен Python 3.11+ (я считал на 3.14).

```bash
python -m venv .venv
.venv/Scripts/python.exe -m pip install -r requirements.txt
```

Кейс 1 работает на стандартной библиотеке, пакеты нужны только для бонусной части Кейса 2 и для Кейса 3.

```bash
cd Кейс1 && ../.venv/Scripts/python.exe analysis.py
cd Кейс2 && ../.venv/Scripts/python.exe discovery.py && ../.venv/Scripts/python.exe schema.py
cd Кейс3 && ../.venv/Scripts/python.exe case3_analysis.py
```

## Данные

- `Кейс1/students1.csv` и `Кейс2/students2.csv` — выгрузки задания, лежат в репозитории.
- `Кейс3/data/` — 43 таблицы, около 4,5 ГБ, плюс `logs.zip` на 5 ГБ. В репозиторий не входят,
  скачиваются публичной ссылкой скриптами `download_data.py` и `fetch_logs.py`. Отчёт можно читать
  без выгрузки: числа по всем шести гипотезам лежат в `Кейс3/out/`.

## Коротко о результатах

**Кейс 1.** Обычное поведение описал по когортам «тип заявки × этап» и по рабочим часам, а не по
календарным. Нашёл 66 отклонений в 56 заявках: 34 нарушения регламента (пропуск согласования,
исполнение до утверждения бюджета, этап закрыт не той ролью, самосогласование), 24 статистических
отклонения и 8 наблюдений, которые требуют ручного обоснования. Правила, которые дали ложные
срабатывания, задокументированы с числами.

**Кейс 2.** Восстановил 10 активностей, один цикл доработки и три финальных состояния. Основной
маршрут — 56,7 % заявок, всего 8 вариантов и 12 переходов. Развилка «дополнительное согласование»
лучше всего объясняется суммой ≥ 150 000, но 19 заявок ей противоречат, поэтому условие помечено
как гипотеза. В бонусной части сравнил ручную модель с Inductive Miner и Heuristic Miner из pm4py.

**Кейс 3.** Шесть гипотез с числами: повторные триалы на мультиаккаунтах (2,3 % всех триалов —
нижняя оценка, верхняя 38,2 %), лимиты бесплатного тарифа (проверяются только прокси-метриками,
байтов в выгрузке нет), время до покупки (триал даёт конверсию 40,6 % против 0,26 %, но 77 % оплат
приходят позже 30 дней), причины неудачных платежей (в основном брошенная корзина, а не сбой),
реферальный канал (конверсия 17,6 % против 0,80 % у органики) и логи клиентов (92,4 % ошибок —
DNS-over-HTTPS, 91,5 % всех ошибок приходятся на 23 дня сентября 2026).
