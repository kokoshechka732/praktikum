# Кейс 2. Восстановление процесса закупки по журналу событий

Задача: исходной схемы процесса нет, есть только журнал выполнения заявок. Нужно восстановить, какие
действия выполняются, в каком порядке, какие развилки и возвраты поддерживаются данными, и показать
это читаемой схемой с обоснованием по журналу.

## Данные

`students2.csv` — 6 508 событий, 1 000 заявок, 48 пользователей, 10 активностей. В отличие от Кейса 1
здесь нет `task_created`, `Status` и `RequestType`, поэтому длительности и типы заявок недоступны:
восстанавливать можно только порядок. Описание полей — в `dataset_description.md`.

## Как считал

Заявки группируются по `ProcessInstanceId`, события внутри заявки упорядочиваются по `EventIndex`.
Перед анализом проверил инварианты: один `process_started` и один `process_completed` на заявку,
`EventIndex` плотный, первая активность всегда «Регистрация заявки», `Amount` внутри заявки не меняется,
пользователей с двумя ролями нет.

Дальше — частоты активностей и ролей, полные варианты маршрута, частоты переходов. Схема строится от
вариантов, а не от графа непосредственно следующих действий: DFG допускает комбинации, которых в
журнале не было (например, исполнение без проверки бюджета).

## Результат

10 активностей, три финальных состояния, один цикл возврата и 8 вариантов маршрута:

- основной маршрут — 56,7 % заявок (567 из 1 000);
- дополнительное согласование с ролью `director` — 20,9 % заявок, в задании этой роли нет;
- доработка — 15,6 % заявок, единственная точка возврата — согласование руководителем;
- отказ — 6,3 %, отмена — 2,6 %.

Условие развилки «дополнительное согласование» лучше всего объясняет сумма ≥ 150 000: она покрывает
все 209 заявок с этим этапом, но 19 заявок с такой суммой прошли без него. Точность 98,1 %, поэтому
на схеме ветка помечена как гипотеза, а не как правило.

В необязательной части сравнил ручную модель с pm4py: Inductive Miner (fitness 0,976, precision 0,841,
3 немых перехода) и Heuristic Miner (0,996 и 0,978). Оба алгоритма допускают больше поведения, чем
было в журнале: 50,9 % и 20,8 % симулированных трасс в данных не встречаются.

## Запуск

```bash
python discovery.py    # варианты, переходы, частоты
python schema.py       # out/schema.svg и out/schema.mmd
python bonus_pm4py.py  # сравнение с pm4py, нужен пакет pm4py
```
